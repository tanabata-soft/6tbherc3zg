# 譜面設計メモ（v1.5.0 / 譜面 v3 の根拠、v1.9.0 で両親指前提＝譜面 v4、v1.10.0 で主レイヤー選択＝譜面 v5）

一般の音楽ゲームの譜面設計論を調べ、このゲームの譜面生成（`scripts/generate-charts.py` v3）と
エンジンの長押し（ホールド）仕様に採用した原則をまとめる。

## 調べて分かった原則

### 1. ノーツは「音楽の層」に対応させる（レイヤリング）
- 曲はドラム・メロディ・ボーカルなど複数の層が重なっている。譜面はその時点で
  **いちばん目立つ層**を拾い、場面で層を切り替えながら進めるのが基本
  （Nyxa's Perfect Mapping Class: "the most prominent instrument in any given part
  of the song is always worth mapping"）。
- **短い音（スタッカート）はタップ、長い音（レガート）は長押し**で表すのが定石
  （同上: "Staccato should almost always be represented with hitcircles, and
  legatos should almost always be represented with sliders"）。
- 日本語の作譜論でも「音取り」＝どの音（メロディ／ピアノ／キック／ボーカル／複数を
  同時に）に合わせるかを先に決めることが手順の最初に来る（UMIGURI の作譜記事）。

### 2. パターンの語彙がある（ランダムに置かない）
osu!mania ガイドが挙げる基本パターン:
- **階段（staircase）/ ロール（roll）**: 一方向へ流れる配置。速い音の連なりに。
- **トリル（trill）**: 2レーンの高速交互。速く入れ替わる2つの音に。
- **縦連／ジャック（jackhammer）**: 同じ音の繰り返しに使う。乱用すると難易度が跳ね上がる。
- **同時押し（chord）**: 強い音（重いドラム・シンバル）の強調。2つ同時が基本。
- **ジャンプストリーム**: 一定の流れの中に、強い音だけ同時押しを混ぜる。
- **バースト**: 短い区間だけ密度が跳ね上がる配置。
- **シールド**: ロングノーツの直前・直後に置くノーツ。
- **ロングノーツ（LN）**: 長い音を表す最良の手段。

### 3. 一貫性とモチーフ
- **同じ音には同じパターンを**。「ドラムに同時押しを使ったら、後でも同じ音には
  同じ扱いをする。一貫性は譜面の最重要要素のひとつ」（osu!mania ガイド）。
- 繰り返しのフレーズでは譜面も同じモチーフを繰り返すと、プレイヤーが
  「曲の繰り返し」を体で感じられる。2回目は少しだけ変える（鏡像・末尾の変化）と
  飽きずに済む、というのが各所の作譜論の共通認識。

### 4. 密度は曲の盛り上がりに一致させる
- サビ（kiai）が最も濃く、静かな節は薄く。密度のグラフが曲のエネルギーと
  似た形になるのが自然（osu!mania ガイドの Hard/Insane 項、Density Graph の考え方）。
- フレーズの切れ目には休みを置く（息継ぎ）。切れ目なく置き続けると単調で疲れる。

### 5. 長押し（ロングノーツ）の置き方
- 長い音・ボーカルの伸ばし・持続音に置く（原則1のレガート対応）。
- **押さえたまま他のノーツを叩く**配置は上級向けの面白さとして確立している
  （CHUNITHM の「敷」属性譜面＝長い HOLD の上に他のノーツを重ねる）。
- osu!mania ガイドの難易度別指針:
  - Easy: 長押し中は他のノーツを置かない（置くなら反対の手側）。
  - Normal: 長押し中のノーツは反対の手側を中心に。
  - Hard: 長押しと細かいタップの組み合わせ、長さの違う長押しの同時使用も可。
    ただし「どの長押しも必ず音に合わせる。ランダムに入れない」。

### 6. 難易度設計（osu!mania ガイドの難易度別指針を要約）
- **Easy**: 1/4（16分）パターンは使わない。1/2（8分）も慎重に。同時押しは
  節の頭・終わりの重いシンバルだけ。両手のバランスを取る。
- **Normal**: 8分中心。16分は慎重に（短い階段だけ）。強いスネア／シンバルに
  同時押し。サビは同時押し＋通常ノーツで盛り上げる。
- **Hard**: 16分バーストと階段、短い同時押しストリーム、短い縦連が解禁。
  サビが最も濃い場所になる。コードトリルは密度が跳ねるので避ける。

## 両親指前提（譜面 v4、v1.9.0）

オーナー指示「基本両手（両親指）でやることを前提にやりやすい譜面にして」を受けて、
v3 の設計に両親指のハード制約を上乗せした。レーンは左から 0,1,2,3 とし、
左親指が 0・1、右親指が 2・3 を受け持つ（side = レーン ÷ 2）。

### 制約（正本は `scripts/check-two-thumb.py`）

- **C1 同時押しは左右に分かれるペアだけ**。同時押しは最大2ノーツ（従来どおり）で、
  組み合わせは 0+2 / 0+3 / 1+2 / 1+3 のみ。同側ペア（0+1 / 2+3）は、片手の親指1本で
  2レーンを同時に押す形になるため禁止する。親指は2本しかないので、3つ以上の
  同時押しがそもそも成立しない、というのが最大2つの根拠でもある。
- **C2 長押し中は、その側の親指は拘束される**。ホールドの帯（頭の時刻より後、
  尾まで）にあるノーツは反対側だけにする。同時押しはペアの片方が必ず拘束側に
  来るため、帯が同時押しの時刻をまたぐ長押し自体を置かない。同時ホールドは
  左右1本ずつまで（同側同士の重なり禁止。現行の生成は重なり自体を作らない）。
- **C3a 速い流れでは同側3連を作らない**。16分相当（細分グリッドで間隔1ステップ
  以下）の連なりの中では、同じ側のノーツは2連まで。片側だけが忙しくなる流れは、
  親指の移動が間に合わず崩れるため。
- **C3b 片手トリルは短区間だけ**。同側2レーンの交互（0-1-0-1 のような片手トリル）は
  8分相当以下の速さ（間隔2ステップ以下）で、4連（半小節1単位）まで。速い片手
  トリルは C3a 側で禁止される。
- **C4 同一レーン連打（縦連）は従来ルールを維持**（hard のみ、間隔170ms以上、
  最大3連）。同じ親指の連打は、間隔さえあれば成立する。

### v3 から置き換えた部分

- **トリルは左右交互に**。v3 のトリル（同側2レーンの16分交互）は C3a に反する
  ため、レーンをまたぐ交互（0↔2 / 1↔3 系）に変えた。左右の親指が交互に受ける
  流れが両親指譜面の基本形になる。
- **wave16 の形を変更**。往復形 [0,1,2,3,2,1,0,1] は右側3連（2,3,2）が出るため、
  左右2連ずつの往復 [0,1,3,2,1,0,2,3] にした（roll は元から左右2連ずつ）。
- **同時押しの相方は反対側から選ぶ**（v3 は全レーンから分布優先で選んでいた）。
- **長押しの帯からは同側ノーツを除く**（v3 は同一レーンだけ除いていた）。
  hard で「長押し＋他レーンタップ」を残す方針は、タップを反対側に限って維持する。
- パターンの語彙そのもの、サビのモチーフ反復、密度のエネルギー連動、入れ子
  （hard ⊇ normal ⊇ easy）、タイミング合わせ（実測拍列の補間＋スナップ）は
  v3 のまま引き継ぐ。

### FEVER 区間の密度（v1.9.0 で追加）

追加のオーナー指示「フィーバー中はノードも多くして、気持ちよく叩けるように」を
受けて、FEVER 区間（＝サビ）の密度を上乗せした。上げ方は両親指制約の内側に限る:

- `plan_phrase` で FEVER ユニットの計画エネルギーを +0.30 底上げし、16分
  パターン（左右交互のトリル／roll／wave16）の確率を 0.42 → 0.62 に上げる。
  burst のゲートが通らなかったユニットは sparse に落とさず、密な8分パターン
  （階段・波・交互・交差）にする（sparse に倒すと底上げが逆効果になる）。
- ゲートのエネルギー条件も同じく底上げする（強さの条件は不変）。
- 難易度導出の間引き（`thin`）では FEVER ノーツを ×1.2 で優先して残す。
  easy は拍位置だけなので増え方は控えめ、normal（8分位置）・hard（全部）で
  しっかり増える、という難易度差が間引きの構造から自然に出る。
- 実測（ノーツ/秒、底上げ前 → 後）: 石畳の FEVER 39秒で easy 1.56 → 1.56 /
  normal 2.56 → 3.05 / hard 3.67 → 4.41。Kiso Night の FEVER 54秒で
  easy 1.48 → 1.80 / normal 2.80 → 3.26 / hard 3.67 → 4.19。

### 担保のしかた

- 生成器は、パターンのフィット選択で C3a/C3b に触れる候補へ罰金を課し、
  難易度導出の後に修復（違反ノーツを落とす。入れ子を保つため下位難易度からも
  落とす）を回す。
- 生成の最後に `scripts/check-two-thumb.py` の `check_charts()` で全譜面を
  検証し、違反があれば charts.json を書き出さずに終了する。チェッカー単体でも
  実行できる（`.venv/bin/python scripts/check-two-thumb.py`）。
- 間隔の判定はミリ秒ではなく細分グリッドのステップ数で行う。スナップで時刻が
  ±38ms 動いても、16分か8分かの判定は揺れないため。

## 長押しの完走タイミング（エンジン仕様。v1.7.1 で明文化）

プレイヤーから見て「帯の見た目の長さ」と「判定の終わり」が一致するための定義。
正本は `src/logic.ts` の `advanceHold` で、単体テスト（tests/hold.test.ts）が固定する。

- **完走は尾の時刻ちょうど**。押し続けている場合、完走の判定・集計・エフェクトは
  ノーツ時刻＋長さ（尾）が判定ラインに届く時刻に起きる。尾の 1ms 前には起きない。
- **tick はスコア専用**。拍ごとの tick は完走タイミングに影響しない（最後の tick が
  尾より前にあっても、それで完走にはならない）。
- **grace（離し直しの猶予 100ms）は尾直前の救済としてのみ働く**。尾の 100ms 以前に
  離した場合は、離したまま尾を迎えても完走扱いにする（ただし完走の表示は尾の時刻
  まで出さない）。尾まで猶予が届かない離し方は失敗（猶予が切れた時点でミス）。
  尾の瞬間に押せていない長押しが、尾より前に「終わった」ように見えることはない。
- **描画と判定は同じ時計・同じオフセット・同じ落下時間**を使い、帯は尾が判定
  ラインに届くまで描き続ける。帯の描画を打ち切る条件は帯そのものの見える範囲で
  決める（頭の仮想位置で打ち切ると、尾より前に帯が消える。v1.7.0 までの不具合）。

## 譜面 v5（v1.10.0、全4曲に適用）

オーナー指示「プレイして気持ちいい譜面をもっと研究して、曲に合った譜面が
作れるように」への対応。調査の正本は `~/workspace/kiso-chart-v5-research.md`。
v4 までは全帯域のオンセット強度だけが「音の強さ」の物差しで、ドラム・旋律・
歌が混ざった強さでパターンを選んでいた。v5 は「いま叩いているのはどの
パートか」を譜面生成に持たせる。当初は1曲（kira）での試行だったが、
オーナー判断で実機確認を待たずに全4曲へ展開した（kira の譜面は試行時の
ものから変えていない）。

### V5-1 特徴量レイヤー

スロットに、主レイヤー判定とゲート用の特徴量を持たせる（生成器の
`compute_layer_features`）:

- **drums** = HPSS の打撃成分のオンセット強度（従来の全帯域に近いが持続音を除く）
- **melody** = HPSS の持続成分の旋律帯域（600〜6000Hz）のスペクトラルフラックス
- **vocal** = 持続成分の声帯域（600〜3000Hz）のフラックス × 有声度
- **F0** = pyin（C2〜C6）の基本周波数（半音、対数）。無声・未検出は NaN
- ほかに帯域別（低 20〜150／中低 150〜600／中 600〜3000／高 3000〜8000Hz）の
  オンセット強度と持続成分 RMS も持つ（将来のレーン割当用）

有声度についての実測上の注意: pyin の `voiced_prob` は絶対値が極端に小さい
（有声判定フレームでも平均 0.14 程度）ため重みに使えない。有声の物差しは
`voiced_flag`（HMM 判定）の ±2 フレーム移動平均に置き換えた。また有声フラグは
持続シンセやオルガンにも立つ（gospel では歌詞区間外の方が有声率が高い）ため、
「ボーカルらしさ」は vocal レイヤー（帯域×有声度）の方で見る。

ゲートの物差しは、レイヤー強度を**全帯域 strength の分布へ順位写像**した
`eff` とする（`_rank_map`）。順位が同じなら値が同じになるため、v3/v4 で
調整してきた閾値（パーセンタイル基準）がレイヤーを変えてもそのまま意味を
持つ。これが v5 を小さく導入できた鍵。

照合（`scripts/analyze-layers.py`、4曲）: melody レイヤーは FEVER 内 > 外が
全曲で明確、vocal レイヤーも全曲で FEVER 内が高い。gospel の vocal は歌詞
区間 0.33／区間外 0.12 と強く対比した。kira は歌が常時シンセリードと重なる
ため vocal の区間対比は弱い（0.35／0.40）が、FEVER 対比は正（0.47／0.33）。
帯域境界の調整は不要と判断した。

### V5-2 フレーズ単位の主レイヤー選択

フレーズごとに主パートを1つ決め（`assign_layer_for`）、そのフレーズでは
パターン選択ゲート・同時押しゲート・難易度導出の密度の床が参照する strength
を主レイヤーの `eff` に切り替える。決め方:

- スコア = フレーズ内スロットのレイヤー強度（p95 正規化）の平均
  ＋曲別バイアス（SONGS の `layer_bias`）＋サビの指定レイヤーへのボーナス
  （`chorus_layer`、標準 +0.30。曲別に `chorus_bonus` で上書きできる:
  night はシンセリードがサビでも強く鳴るため 0.45）
- **サビは連続するフレーズを1グループとして、グループ全体で1回だけ決める**
  （サビの中で主レイヤーが揺れないように。入り口でヒステリシスを効かせると
  意図した切り替えまで妨げられるため）
- 通常フレーズ間はヒステリシス 0.08（差がこれ未満なら直前の主レイヤーを継続）
- 全レイヤーが弱い（最良スコア < 0.16）フレーズは mixed＝全帯域（v4 の挙動）

**burst ゲートだけは主レイヤーで測らない**（全曲展開時に判明）: 持続成分の
フラックスは16分位置のすべてで高く出るため、主レイヤーの eff を burst
ゲートに使うと、曲によっては16分パターンが過剰になる（highway で trill/roll
が爆発し、間引きの上限に引っかかって easy が 75 ノーツまで崩れた）。burst の
根拠（裏の16分に速い連打があるか）は曲ごとに担うパートが違うので、
SONGS の `burst_basis` で取り方を選ぶ:

- `main`（kira）: 主レイヤーの eff。シンセのアルペジオが16分を担う
- `drums`（highway / gospel）: 全帯域のオンセット（v4 の物差し）か、打撃成分
  （ドラム＝ハットやフィルの16分）の eff
- `main65`（night）: drums の条件＋主レイヤーの eff が特に強い（p65 以上）
  場合。シンセリードの16分は強い場所だけ拾う

曲ごとの割当結果（フレーズ単位）:

- **kira**: 小節2〜39 melody／サビ（40〜60）vocal／以降 melody。
  方針「シンセメロディ主体、サビはボーカル」と一致
- **highway**: 小節2〜25 drums（Aメロはドラムの骨格）／26 vocal（1小節の
  ブレイク）／27〜31 melody／サビ（32〜53）は melody／54〜58 melody。
  サビは chorus_layer=drums でボーナスを付けても、リフ（melody）が僅差
  （0.808 対 0.800）で勝った。リフ主体のサビとして許容範囲と判断
- **night**: Aメロ・Bメロは melody（シンセリード）。サビは2区間のうち
  1回目（小節26〜41）が melody、2回目（60〜79）が vocal。1回目はシンセ
  リードの特徴量がボーカルを上回り、ボーナス 0.45 でも切り替わらなかった。
  「最後のサビでボーカルに切り替わる」形として受け入れる
- **gospel**: 全フレーズ vocal。方針「リードボーカル主導」と一致
  （小節54〜60 は melody の生値が僅差で上だが、バイアスで vocal を維持）

### V5-3 音高コンター

主レイヤーが melody/vocal のフレーズでは、パターンのレーン fit コストに
音高の動きを反映する（`Realizer.fit_cost` の `f0s` 引数）:

- 前ノーツとの F0 差が 1 半音以上: 同方向のレーン移動 −0.20／逆方向 +0.45／
  レーン不動 +0.15（ピッチが動くのにレーンが止まるのも不自然なため）
- F0 差が 0.5 半音未満でレーンが動くと +0.08（同音なのに跳ぶ罰金）
- 同音反復の検出（半小節の相対位置 0,2,4 の F0 が最大−最小 < 0.6 半音）は

### chord_gate_drop の扱い

- **kira（16）は v5 でも外せなかった**: ゲートを主レイヤーの eff に替えても、
  drop なしでは hard の同時押しが5組止まりで設計基準（8組以上）を割る。
  理由: 曲全体の強弱が均一で、小節頭スロットの相対的な弱さはレイヤーを
  変えても残るため。drop 併用（eff ゲート＋16）では hard 10組になる
- **gospel に 14 を新規追加**: ゲートがボーカルの eff を見るようになると、
  小節頭がボーカルの休みやオルガンの持続に当たることが多く、hard の
  同時押しが15→4組まで減ったため。drop 14 で14組に戻った
- highway / night は不要（drop なしで hard 8組・13組）

### V5-4（長押しの持続音ベース化）は今回見送り

gospel の長押しは、V5-2 の時点で既に v4 と同等以上（本数 4/10/15 →
6/10/15、hard の総延長 15.5→15.9 秒）になっており、候補の選定条件

改善に対して生成器の変更範囲が大きいため、将来の課題として残す。
