# 譜面設計メモ（v1.5.0 / 譜面 v3 の根拠）

一般の音楽ゲームの譜面設計論を調べ、このゲームの譜面生成（`scripts/generate-charts.py` v3）と
エンジンの長押し（ホールド）仕様に採用した原則をまとめる。

## 調べて分かった原則

### 1. ノーツは「音楽の層」に対応させる（レイヤリング）
- 曲はドラム・メロディ・ボーカルなど複数の層が重なっている。譜面はその時点で
  **いちばん目立つ層**を拾い、場面で層を切り替えながら進めるのが基本
  （Nyxa's Perfect Mapping Class: "the most prominent instrument in any given part
  of the song is always worth mapping"）。
- **短い音（スタッカート）はタップ、長い音（レガート）は長押し**で表すのが定石
  （同上: "Staccato should almost always be represented with hitcircles, and
  legatos should almost always be represented with sliders"）。
- 日本語の作譜論でも「音取り」＝どの音（メロディ／ピアノ／キック／ボーカル／複数を
  同時に）に合わせるかを先に決めることが手順の最初に来る（UMIGURI の作譜記事）。

### 2. パターンの語彙がある（ランダムに置かない）
osu!mania ガイドが挙げる基本パターン:
- **階段（staircase）/ ロール（roll）**: 一方向へ流れる配置。速い音の連なりに。
- **トリル（trill）**: 2レーンの高速交互。速く入れ替わる2つの音に。
- **縦連／ジャック（jackhammer）**: 同じ音の繰り返しに使う。乱用すると難易度が跳ね上がる。
- **同時押し（chord）**: 強い音（重いドラム・シンバル）の強調。2つ同時が基本。
- **ジャンプストリーム**: 一定の流れの中に、強い音だけ同時押しを混ぜる。
- **バースト**: 短い区間だけ密度が跳ね上がる配置。
- **シールド**: ロングノーツの直前・直後に置くノーツ。
- **ロングノーツ（LN）**: 長い音を表す最良の手段。

### 3. 一貫性とモチーフ
- **同じ音には同じパターンを**。「ドラムに同時押しを使ったら、後でも同じ音には
  同じ扱いをする。一貫性は譜面の最重要要素のひとつ」（osu!mania ガイド）。
- 繰り返しのフレーズでは譜面も同じモチーフを繰り返すと、プレイヤーが
  「曲の繰り返し」を体で感じられる。2回目は少しだけ変える（鏡像・末尾の変化）と
  飽きずに済む、というのが各所の作譜論の共通認識。

### 4. 密度は曲の盛り上がりに一致させる
- サビ（kiai）が最も濃く、静かな節は薄く。密度のグラフが曲のエネルギーと
  似た形になるのが自然（osu!mania ガイドの Hard/Insane 項、Density Graph の考え方）。
- フレーズの切れ目には休みを置く（息継ぎ）。切れ目なく置き続けると単調で疲れる。

### 5. 長押し（ロングノーツ）の置き方
- 長い音・ボーカルの伸ばし・持続音に置く（原則1のレガート対応）。
- **押さえたまま他のノーツを叩く**配置は上級向けの面白さとして確立している
  （CHUNITHM の「敷」属性譜面＝長い HOLD の上に他のノーツを重ねる）。
- osu!mania ガイドの難易度別指針:
  - Easy: 長押し中は他のノーツを置かない（置くなら反対の手側）。
  - Normal: 長押し中のノーツは反対の手側を中心に。
  - Hard: 長押しと細かいタップの組み合わせ、長さの違う長押しの同時使用も可。
    ただし「どの長押しも必ず音に合わせる。ランダムに入れない」。

### 6. 難易度設計（osu!mania ガイドの難易度別指針を要約）
- **Easy**: 1/4（16分）パターンは使わない。1/2（8分）も慎重に。同時押しは
  節の頭・終わりの重いシンバルだけ。両手のバランスを取る。
- **Normal**: 8分中心。16分は慎重に（短い階段だけ）。強いスネア／シンバルに
  同時押し。サビは同時押し＋通常ノーツで盛り上げる。
- **Hard**: 16分バーストと階段、短い同時押しストリーム、短い縦連が解禁。
  サビが最も濃い場所になる。コードトリルは密度が跳ねるので避ける。

## このゲームに採用する原則（譜面 v3）

土台（v2）は維持する: 実測拍列への補間グリッド、オンセットピークへのスナップ、
ズレ検証（回転ドリフトなし）、FEVER 区間は不変更、表示 BPM は実測値（135/150）。

1. **フレーズ単位でパターンを割り当てる**。曲をフレーズ（節の切れ目＝FEVER境界と
   エネルギーの落ち際で区切る）に分け、1〜2小節ごとに語彙から型を選んで割り当てる:
   階段／波（往復階段）／交互／トリル／縦連／交差（ジグザグ）。ランダムな強度順の
   選択（v2方式）はやめ、「型の連続」として譜面を組み立てる。
2. **モチーフの再登場**。サビ（FEVER区間）のフレーズでは、最初のサビで使った
   パターンの並びを後のサビでも再登場させる。2回目以降はレーンを鏡像にするか
   末尾のパターンを変える。サビ内でも前半のパターンを後半で繰り返す。
3. **同時押しは強いアクセントに**。サビの小節頭など特に強い拍に2レーン同時押し。

## 長押しの完走タイミング（エンジン仕様。v1.7.1 で明文化）

プレイヤーから見て「帯の見た目の長さ」と「判定の終わり」が一致するための定義。
正本は `src/logic.ts` の `advanceHold` で、単体テスト（tests/hold.test.ts）が固定する。

- **完走は尾の時刻ちょうど**。押し続けている場合、完走の判定・集計・エフェクトは
  ノーツ時刻＋長さ（尾）が判定ラインに届く時刻に起きる。尾の 1ms 前には起きない。
- **tick はスコア専用**。拍ごとの tick は完走タイミングに影響しない（最後の tick が
  尾より前にあっても、それで完走にはならない）。
- **grace（離し直しの猶予 100ms）は尾直前の救済としてのみ働く**。尾の 100ms 以前に
  離した場合は、離したまま尾を迎えても完走扱いにする（ただし完走の表示は尾の時刻
  まで出さない）。尾まで猶予が届かない離し方は失敗（猶予が切れた時点でミス）。
  尾の瞬間に押せていない長押しが、尾より前に「終わった」ように見えることはない。
- **描画と判定は同じ時計・同じオフセット・同じ落下時間**を使い、帯は尾が判定
  ラインに届くまで描き続ける。帯の描画を打ち切る条件は帯そのものの見える範囲で
  決める（頭の仮想位置で打ち切ると、尾より前に帯が消える。v1.7.0 までの不具合）。
